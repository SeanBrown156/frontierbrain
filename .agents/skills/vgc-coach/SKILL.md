# VGC Coach

Read `context/player.md`, `knowledge/mechanics/champions.md`, `tools/README.md`, and applicable exact team records. For a normal daily review, run `npm run daily` to ingest only workspace HTML and generate observable summaries. For an explicitly scoped UI review, use its frozen request instead; do not run daily, refresh or review-mark, and return structured findings/report without file edits. Read `replays/index.json`, `reports/replay-reviews/overview.md` and new parsed games; don't assume autogenerated review questions are completed coaching.

## Review

- Identify the player's side by normalized username: `player` and `aliases` in the data directory's `config.json`. Read format, team sheets and selected team size from the log. Offered OTS is not accepted OTS. Unknown back slots remain unknown if never revealed.
- Review preview, leads, bring-four, win conditions, position, priority/speed control, targeting, switches, Protect, weather/terrain, Mega timing, setup and endgames. Use turn-start `knowledgeBefore` and event line references to avoid hindsight.
- Distinguish observed mistake, reasonable risk, matchup weakness, execution problem and variance. Give plausible alternatives and opponent counterplay; do not claim an alternative guarantees a win without proof. Unknown selected moves for a flinched/fainted Pokémon cannot be invented.
- Calculate decisive thresholds only with recorded exact own sets or explicitly labelled assumptions. Rounded opponent HP is an interval, not an exact stat/damage value. Crits, secondary effects, items and chip must be accounted for. Compare lines against multiple plausible opponent sets.
- Inspect PASRS-style lead/bring/move/matchup/attendance metrics with counts and team version filters. The four-appearance highlight threshold is only a reporting convention, not statistical confidence. Do not infer causation from correlated selections or remove support moves merely because they were rarely clicked.
- Read associations in `replays/associations.json` and frozen team configurations under `teams/<id>/` with Pokémon revisions under `pokemon/<id>/`. For scoped UI reviews, the supplied snapshot is authoritative. A family association or roster suggestion is not an exact set attachment. Only `certainty: exact` selects the frozen formula configuration and bank revision IDs; never use a team's current revision for old games. Check observed moves against any proposed attachment. User-imported pastes can be newer than matching replays.

## Deliver

For each new replay write a coaching section with preview assessment, pivotal turns, better lines/counterplay, confidence/unknowns, and one practice target. Link the local original, replay ID, turn and log line. Write a digest of recurring patterns, prioritized actionable changes and experiments. Save candidate revisions separately using the teambuilding workflow; preserve active teams.

For ordinary daily batches (not scoped UI reviews), after the coaching report is successfully saved, run `npm run vgc -- review-mark <replay-id> <relative-report-path>` for each covered game. Unreviewed games remain queued for retries. No new games: record the empty scan without repeating advice. Bo3 grouping requires established set identity; never group nearby games just by opponent or roster. Video ingestion is deferred.
